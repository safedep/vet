# vet v2.0.0

vet v2 is a new release line. It keeps the job of vet, to find supply chain risk before it
reaches production, and changes the command line, the report, the policy and the config. This
page lists each change that a v1 user must make. v1 gets security fixes only.

## What is new

- **Controls.** Each finding comes from a control with a stable id: `malware`,
  `suspicious-package`, `vulnerability`, `dependency-cooldown`, `untrusted-registry`,
  `registry-path-mismatch`, `dangerous-trigger`, `template-injection` and `unpinned-action`.
  `vet policy control list` prints them.
- **One report.** Every format comes from the same records: a header, the manifests, the
  packages, the findings, the diagnostics and a trailer with the summary and the gate.
- **Pull request mode.** `vet scan --base-ref REF` reports only what the change adds.
- **Saved scans.** vet saves each scan. `vet report show` renders it again in any format with no
  new scan. A scan that stops continues on the next run.
- **Policy v2.** Rules with `fail` or `warn`, and suppressions with a reason and an expiry.
- **Agent mode.** For `CLAUDECODE` or `AI_AGENT`, or with `--mode agent`, vet writes JSON, never
  prompts and prints one `ERR:` line for each error.
- **No CGO.** The release binaries are static.

## Exit codes

| Code | v1 | v2 |
| --- | --- | --- |
| 0 | No violation | The gate passed, or no gate was set |
| 1 | A violation with `--filter-fail`, or an error | The gate failed |
| 2 | Not used | A usage or config error |
| 3 | Not used | A runtime error |
| 130 | Not used | A signal stopped vet. The scan continues on the next run |

| `--enrich=false` | Removed. A scan needs the data to run the controls |

| `--skip-github-dependency-graph-api` | Removed |

| `--verbose`, `--debug`, `--log FILE` | `-v`. The `--mode` flag sets the terminal view |

## Report flags

`--report FORMAT=PATH` writes one format to a file. One scan writes many formats. `-o FORMAT`
writes one format to stdout.

| v1 | v2 |
| --- | --- |
| `--report-json FILE` | `--report json=FILE`. The schema changed. See below |
| `--report-sarif FILE`, `--report-sarif-vulns`, `--report-sarif-malware` | `--report sarif=FILE`. It has every finding |
| `--report-markdown FILE`, `--report-markdown-summary FILE` | `--report markdown=FILE` |
| `--report-cdx FILE`, `--report-cdx-app-name` | `--report cyclonedx=FILE` |
| `--report-summary` and its options | The terminal view of `vet scan` |
| `--report-csv`, `--report-html`, `--report-graph` | Removed. Convert the `json` or `jsonl` report |
| `--report-gitlab FILE` | `--report gitlab=FILE` |
| `--report-bitbucket-meta`, `--report-bitbucket-annotations` | `--report bitbucket=FILE`. One file holds the report and the annotations |
| `--report-defect-dojo` and its options | Removed |
| `--report-sync` and its options | Removed. The SafeDep Cloud report plugin comes in v2.1 |

each value.

## The JSON report

The v1 JSON report was one document with `meta`, `manifests` and `packages`, and each package
held its violations, advices and insight data. The v2 report is a stream of records between a
header and a trailer. `vet report schema get` prints its JSON Schema, and `schema_version` names
its version.

| v1 | v2 |
| --- | --- |
| `meta` | `header`: the tool, the scan id, the target, the mode and the base ref |
| `manifests[]` | `records[]` with `kind: manifest` |
| `packages[].package`, `packages[].manifests` | `records[]` with `kind: package`, with `manifest_ids`, `insight` and `malware` |
| `packages[].vulnerabilities[]` | `records[]` with `kind: finding` and `control_id: vulnerability` |
| `packages[].malware_info[]` | `records[]` with `kind: finding` and `family: malware` |
| `packages[].violations[]` | `records[]` with `kind: finding`. A finding that a suppression hides has `suppression` |
| `packages[].advices[]` | `finding.remediation` |
| `packages[].threats[]` | `records[]` with `kind: finding` from the lockfile control |
| Not present | `records[]` with `kind: diagnostic`: a backend that did not answer, a file that vet could not read |
| Not present | `trailer.summary` and `trailer.gate` |

## Policy

A v1 filter was a CEL expression over a package. A v2 rule is a CEL expression over a finding,
its package and its manifest.

```yaml
# v1 filter suite
filters:
  - name: critical-vulns
    value: vulns.critical.exists(p, true)

# v2 policy
version: 2
rules:
  - id: critical-vulns
    when: finding.control_id == "vulnerability" && finding.severity == "critical"
    action: fail
```

A v1 exception becomes a v2 suppression:

```yaml
suppressions:
  - purl: pkg:npm/left-pad@1.3.0
    reason: Reviewed. Not reachable.
    expires: 2026-12-31
```

`vet policy init` writes a starter policy. `vet policy schema get` prints the fields that a rule
reads. `vet policy validate` checks a file.

## Install

v2.0.0 ships on Homebrew (`brew install safedep/tap/vet`), on the releases page and with
`go install github.com/safedep/vet/v2/cmd/vet@latest`. The npm package and the container image
stay on v1 for this release.
